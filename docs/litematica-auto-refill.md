# 投影轻松放置与打印机自动补货

版本：halfmasa `1.6.0`。客户端功能已纳入全部支持版本的公共预处理源码；逐版本构建和归档结果见 [版本适配记录](version_compatibility.md)。

客户端移植不改变 FGA 服务端支持范围：对应服务器必须提供文中库存频道。现有 FGA 26.3 接口不能直接安装到其他 Minecraft 版本；请使用对应版本实现相同协议的服务端。默认关闭，可自定义开关快捷键。

## 安装与授权

客户端安装 halfmasa、MaLiLib、匹配游戏版本的 Litematica（已核对 1.21.1 的 0.19.61、1.21.5 的 0.22.5、26.2 的 0.28.4 和 26.3 的 0.29.1 接入结构）和 Fabric API。客户端无需安装 FGA；若已安装注册了库存频道的 FGA，会复用其协议 DTO。

服务端安装提供 `playersort/query`、`playersort/take`、`playersort/reply` API v1 的 Carpet FGA Addition，并配置好分类库存假人。普通玩家需要管理员授权：

```text
/fga playersort permission stock 玩家名 true
/fga playersort permission inventoryTake 玩家名 true
```

在 halfmasa 的“扩展功能”栏打开“投影轻松放置自动补货”，并在 Litematica 开启轻松放置。

“投影补货静默取物”（`litematicaRefillSilent`）是默认关闭、可绑定快捷键的子选项。开启后，直接取货及查询来源后的取货使用 FGA 静默接口（新版优先 `playersort/take_amount` 的 silent 标志，旧版为 `playersort/silent_take`）：离线来源直接扣减已验证的存档库存，不召唤或下线假人；已经在线的来源使用在线库存并保持在线。必须更新 FGA 服务端；没有静默频道时暂停并提示，不自动切换回召唤模式。关闭该选项恢复普通模式。


## 其他模组扩展栏与独立子选项

两项功能位于 **其他模组扩展** 页，点击主项的展开按钮查看子项；均默认关闭，可绑定主开关快捷键。原来的投影补货与静默配置从 Ported 迁移，数量、允许取货和展开状态仍保存在 Extensions 配置项中。

| 主项 | 子项 | 默认值 |
| --- | --- | --- |
| 投影轻松放置自动补货 | 投影允许从假人库存取货 / 投影取货数量 / 投影补货静默取物 | 开 / 32 / 关 |
| 打印机自动补货 | 打印机允许从假人库存取货 / 打印机取货数量 / 打印机静默取物 | 开 / 32 / 关 |

允许取货与静默开关可分别绑定快捷键。关闭任一主开关或对应的允许取货选项，取消未提交的取货；已经发出的请求保持原编号并等待最终回复，不重复扣货。修改数量不改变已经提交的请求。

新版 FGA 广告 `query_amount` 和 `take_amount` 后使用数量接口；客户端传物品ID和有界数量，由服务器权威扣货、交付并同步背包。旧服务器仅可选0或与该物品半组相等的值，其他数量暂停并提示升级。没有渠道时不会连续发送半组凑数。单个来源及单一组件必须足量，不跨假人凑数量。

## 打印机改版接入

基线为用户实例内 `litematica-printer-beta25.jar` 的26.3 Hana子包，检查了其真实字节码方法描述符。源码参考：[Yur1Ca/Hana](https://github.com/Yur1Ca/litematica-printer)、[BiliXWhite 同系库存检查](https://github.com/BiliXWhite/litematica-printer/blob/master/src/main/java/me/aleksilassila/litematica/printer/utils/InventoryUtils.java)。没有复制第三方打印算法或替换其放置行为。

- 新版 Hana / 保留同接口的分支：拦截 `MaterialRequestCoordinator.request(List<Item>, Item, Source)` 的 PRINT 请求，仅在原有库存提供者返回 UNAVAILABLE 后补货，PENDING/AVAILABLE 不抢占；收到背包后由打印机原流程继续。
- 旧版 Hana/BiliXWhite 同系 / 保留同接口的26.3改版：在 `InventoryUtils.playerHasAccessToItems(LocalPlayer, Item[])` 返回false时记录缺料，保留原返回值，同步后打印机继续原材料检查。
- ZXY 改版：已核对用户 1.21.11 的 `litematica-printer-1.21.11-2.4+20260330.10.jar`，在 `printer.zxy.inventory.InventoryUtils.switchToItems(LocalPlayer, Item[])` 因全部可接受材料缺失而返回 false 时请求补货；保持原返回值，收到材料后由打印机下一次扫描继续。
- 按方法描述符检测入口，Hana 协调器、通用库存检查和 ZXY 适配互斥，不按版本号限定。改包、改方法或返回结构的未知分支不声称兼容；开启时缺少上述入口会提示，需提供对应游戏版本的 JAR 增加适配。其他版本同样按运行时类名和方法描述符检测，不同包名或入口仍需单独适配。
- 两功能共用一个在途事务和请求编号。打印机一次扫描有很多缺料时先完成当前材料，不因不断切换需求中断中文直取后的查询回退。缺貨或容量不足按材料10秒退避；不确定取货结果暂停至重连。
- 背包或随身潜影盒已有任一种可接受材料时，不查询假人；不会替打印机拆随身盒子，仍由原 QuickShulker 等提供者取本地材料。

人工验收新增步骤（未运行）：在“其他模组扩展”栏打开/折叠两组，重进检查设置保持；关闭允许假人取货时不发查询。加载含两种耗尽材料的投影，启用打印机，分别用1、64、128、0补货并核对库存差额；连续缺料时只串行取货。测试缺货、背包满、静默、编号后位，以及停止打印/关闭开关后的请求收尾。没有打印机安装时应正常启动，开启该项则提示未检测到接口；其他改版须用对应26.3游戏实例验收。

## 行为

- 开启功能后，在投影确定所需材料时检查库存，不因空手或投影的后续放置条件拒绝而跳过补货；只有背包（含快捷栏、副手）以及随身潜影盒内都没有对应物品时，才查询服务端库存并取货；有一个对应物品也不会请求外部补货
- 检查所有颜色的潜影盒，只读取盒内一层物品；不自动取出盒内材料、不检查末影箱或递归扫描其他容器
- 查询等待、继续分页和准备取货时再次检查本地材料；如果对应物品已进入背包或潜影盒，取消尚未提交的请求；已提交的取物仍按原编号等待结果
- 按投影要求的物品 ID 取货，默认32个，可设1–2304个；设0时按服务端堆叠上限取半组（64→32、16→8、不可堆叠→1）。指定数量需要新版FGA，单个来源不足或背包放不下时不部分扣货
- 优先发送 `playersort/direct_take`，服务端根据物品 ID 推导无前缀、无后缀的中文假人名（例如 `minecraft:glass` → `玻璃`），一次请求完成校验和取货，无需先发库存查询。中文来源不存在、数量不足或身份不合格时，才回退分类查询，查找盒装、分号及配置名称的其他库存；旧服务端未提供该频道时直接走查询流程
- 每次补货都创建新的直接取货请求编号；超时仅重发原编号，服务端复用结果，不能重复扣货。取货不再受投影放置冷却、放置缓存和射线探测结果限制；背包同步后的实际放置仍走投影原生检查
- 查询与取物共享递增编号，查询至少间隔 1.1 秒，取物至少间隔 1.1 秒，任意发包至少间隔 300 毫秒
- 服务端返回成功后仍等待玩家的原版背包更新；不会在客户端创建物品
- 使用投影原生放置流程重试，保留距离、方块状态、协议等检查；目标位置或物品变了则取消重试
- 切换世界、打开界面、关闭开关或切换轻松放置模式后取消未提交取物的请求；已经提交的取物等原请求结束
- 查询超时 3 秒、取物超时 15 秒，各最多重发一次原请求；整个流程有 60 秒上限
- 缺货、背包满等错误只停止本次操作，持续按住放置键时不刷请求；松开使用键和自定义轻松放置键后可重新尝试，也可直接换其他材料，不需要切换功能开关
- 切换所需材料时使用最新操作目标；上一查询或取物尚未返回时提示等待，等原请求结束后再查询新材料；不会把旧材料的查询 token 用于新物品
- 权限不足、服务端禁用或协议不支持时暂停本连接的请求并提示；修复后可重新打开开关
- 取物超时或转移结果不确定时停止进一步取物，检查背包后重连恢复；切换开关不会解除这项保护

## 游戏内验收（未由 Codex 执行）

1. 在测试服务器准备分类石头库存，生存玩家背包不带石头，对投影石头执行轻松放置：应收到半组石头并自动重试原位置；长按连续放置用完后应再次补货
2. 分别关闭和开启 Litematica 的 `easyPlacePostRewrite`，重复上一步；每次补货只能扣一次库存
3. 玩家背包或副手已有一个石头时执行轻松放置，不应请求服务端库存；背包没有散装石头但潜影盒里有石头（分别检查无色、染色盒及多个盒）时，也不应请求服务端库存；将最后一个石头用完后，应查询并取半组
4. 补货期间转头、打开背包、关闭开关或切换世界，应取消后续放置，不能在新目标放置旧请求方块
5. 无 API 服务端、未授权玩家、分类库存不足和背包满的情况，应给出提示并停止刷请求
6. 断线重进应清理原请求；客户端同时安装新版 FGA 时不应重复注册频道
7. 人为延迟服务端响应，确认重发相同取物编号不会重复扣货；无法确认取物结果后应暂停至重连
8. 对缺货的黑色染色玻璃请求一次，再切换有库存的石头，应继续查询并取货；补足玻璃库存后，松开放置键再按，应重新查询玻璃，不需重启功能
9. 查询或取货等待期间切换为另一种缺少的材料，应提示等待上一请求；上一请求结束后查询新材料，不继续取旧查询的库存
10. 旧、新轻松放置模式均检查空手补货，即使原生放置条件暂时不满足也应有查询提示；实际放置仍须通过投影原生检查
11. 更新客户端及 FGA 服务端后，用中文假人 `玻璃` 的库存连续补货至少两次：每次先显示直接取货，成功取 32 个，来源等量减少；中文首位缺货时再显示回退查询，并能从有效分号或配置名称库存取货。身份不合格的来源不得扣货；旧服务端继续查询补货
12. 普通模式在首次补货后立即耗尽材料，连续补货至少三次，不应再出现第二次不召唤或上线超时。开启静默选项后重复三次，来源始终不应上线，双方数量每次增减一致；关闭并重启服务端后来源库存应保持减少后的数量。中文首位缺货时，查询找到的其他有效来源也不得被召唤。背包满、来源被手动使用和读取/写入失败不得重复扣货

协议依据：`D:/ai/carpet-fga/docs/playersort_inventory_api.md`。本轮仅同步客户端，FGA 服务端由独立任务维护；客户端不直接修改玩家存档。
