# Conflux Map 0.1.10+ 兼容适配

当前实现由 Minecraft 26.3 基线同步到全部支持版本：1.21.1、1.21.3、1.21.4、
1.21.5、1.21.8、1.21.10、1.21.11、26.1.2、26.2、26.3。

## 根因与选择规则

旧 `ConfluxMapTeleportScreenMixin` 匹配 `OptionalInt` 参数，并在地图界面中寻找
`OptionalInt.isPresent()`。Conflux Map 已将传送参数改为地表查询，0.1.10 起使用
captured + predicted 两个查询，菜单许可也移到了 `teleportPositionKnown`。
原来的 `require=0` 使匹配失败不报错，设置因而静默失效。

新适配读取未加载类的字节码检测接口，不提前加载 Mixin 目标：

| 功能 | 新公开 API 存在 | 0.1.10 / 0.1.11 |
| --- | --- | --- |
| 兜底高度 | `teleportLandingResolve` | 双查询原生界面的独立适配 |
| 列表打开默认筛选 | `waypointListOpening` | 原有初始筛选适配 |
| 地图动作后关闭 | `locationActionPerformed` 和 `closeFullscreenMap` | 原有地图动作完成后的关闭语义 |
| 合并列表、紧凑网格 | 继续使用经过检查的原生界面适配 | 同左 |
| 临时路径点 | 保留现有公开 Waypoint API 实现 | 同左 |

每项新旧路径互斥。接口通过可选反射访问，不引入必装依赖，也不将上游 API 打包进
HalfMasa。监听器读取当前配置；重复 Tick 不重复注册，关闭扩展或 API 实例销毁时注销。
监听失败会记录并注销相应监听器，避免异常中断上游其他插件的事件通知。

## 高度规则

保留配置键 `confluxMapUnknownHeight` 和已保存的数值，仅修正文案和应用条件：

- 已加载的同维度区块：由原生逻辑采样实际地面。
- 已缓存的真实地形：保留原生落点。
- 空柱：无法获得实际地面时使用配置的玩家落脚 Y。
- 离线浏览中的未知落点：使用配置 Y。
- 实时世界中的未知区块：保留原生分阶段传送与加载后的修正。

加载状态通过 `getChunkSource().getChunk(..., FULL, false)` 查询，不主动加载区块。
不能使用客户端 `hasChunk()`：其原版实现始终返回真，会把未加载目标误判成已加载地面。

旧版需要兜底时调用原生 `teleportExact`，坐标保持方块中心，取消原来的地图动作，
避免另发一次指令或留下延迟修正任务。权限、命令模板和服务端限制仍由原生流程负责。
动作事件只表示动作已执行，不表示服务器已经确认传送成功。

## 新 API 基准与验证边界

适配对照 [上游 API 文档](https://github.com/Conflux-Union/conflux-map/blob/bfcac5326994a1088402a7205d665f87c9949a83/docs/api.md)，
锁定提交 `bfcac5326994a1088402a7205d665f87c9949a83`。编写时最新正式版本为
0.1.11；新 API 为主分支接口，不能将契约测试描述为未发布整包的实机验证。

`scripts/python/test_conflux_compat.py` 使用锁定的上游 API 源码检查事件、热修改配置、
注销及重建监听器，并使用官方 Conflux Map JAR 内的模型检查旧版落点策略。
通过 `CONFLUX_TEST_JAR` 分别指定官方 0.1.10 / 0.1.11 JAR。

`scripts/python/run_conflux_grid_smoke.py` 启动隔离客户端和本地服务器，检查合并列表、
紧凑布局、原生操作、资源包主题，以及真实地图动作中的兜底高度、关闭地图和任务取消。
客户端使用 `--jvm-arg=-Xint` 可避开本机此前出现的 Java 原生编译进程退出；该参数只用于测试。

跨版本回归脚本 `scripts/python/run_compat_fixes_smoke.py` 同时验证真实地图动作、
合并列表及自动进食中断。26.x 搭配 Conflux Map 0.1.11 时，测试使用
`--loader-version 0.19.5`，满足该联动模组要求的 Fabric Loader 0.19.0 以上版本。

新版本仍须按实际接口验证，不能保证任意未来版本都兼容；接口改变时应补充测试再更新适配。

## 2026-10-20：26.3 临时路径点高度排查

使用 HalfMasa 1.7.1 与官方 Conflux Map 0.1.12，在原版默认草方块超平坦中，
经 MaLiLib `KP_PLUS` 按下及释放事件触发 HalfMasa 临时路径点。
地表草方块在 Y=-61，人物站立脚部在 Y=-60，路径点保存的是人物脚部位置。
实测 Y=-60、-32.625、128.375、192，API 返回值和本地存储均与按键快照一致；
排队后移动人物也不会覆盖原先坐标。

另外使用实例中的其他模组和 MaLiLib 0.30.2、Fabric API 0.164.0 进行隔离检查，
四组按键创建、存储和原生编辑框数值均一致。测试未复制用户配置，并排除了版本不匹配的
GCA 包装及 Litematica Printer，不能据此宣称用户完整配置下的问题已修复。
核心计时和回归使用 Java 25 `-Xint`；较大模组组合作为补充检查使用 C1 编译模式
`-XX:TieredStopAtLevel=1`。该选项仅属于测试环境设置。

提供的日志中 Y=-142 的传送对应存档中的旧死亡点，并非临时路径点。
现有证据未复现临时路径点 Y 写错，暂不对坐标增加偏移或替换为地图地形高度。
`scripts/python/run_food_waypoint_smoke.py` 可复测创建、存储和原生编辑框显示。

## 2026-10-21：26.3 公共副本与紧凑选择框

在 Conflux Map 扩展下启用“快捷发布公共路径点”（默认关闭），即可在紧凑模式
本地点悬停面板中使用“设置为公共路径点”。该按钮通过原生 `SharedWaypointClient.create`
发布公共副本，不删除、迁移或改写本地点；本地 UUID、分组和公共条目相互独立。
服务端仍需支持并允许发布，按钮沿用原生 `canCreate` 和不可用原因。
待处理时显示“发布中…”，已同步的相同位置显示“已公开”，均禁止重复提交。
公共发布的协议、回执、失败提示及配额由 Conflux Map 原生服务管理。

紧凑卡片右侧的方框属于原生批量选择，不是可见性或公开状态开关。
它与悬停面板方框共用 `selectedWaypointIds` 和 `toggleSelected`，可用于原生分组移动；
仅对可写本地点启用。公共点和跨世界只读点不添加批量选择框。
卡片文字为选择框预留空间，滚动后更新可见控件；悬停操作面板优先处理输入。
关闭快捷发布只隐藏发布按钮，保留已发布公共副本和本地点；选择框随紧凑布局提供。

上述功能以 Minecraft 26.3 为实现与验证基线，现已扩展至全部十个支持构建目标；跨版本验证记录见后文。
`scripts/python/run_conflux_publish_smoke.py` 使用隔离客户端和独立 Fabric 测试服务端，
验证默认关闭、发布公共副本、本地点与分组保留、重复提交、服务端关闭后的禁用状态、
双向勾选同步、原生批量移动、滚动和窄窗口操作布局。
本机 Java 25 C1 模式在功能检查前出现过 Windows 原生退出（0xC0000005），
因此正式功能回归使用 `-Xint`；这属于测试环境记录，不是模组修复内容。

本次最终构建在 Conflux Map 0.1.12 上通过 42 项新增功能检查；在 0.1.10 上
通过原有界面回归（1484 项断言，含布局参数组合），覆盖编辑、删除、显隐、
定位、滚动、资源包主题和真实传送。0.1.10 回归保持新发布开关关闭，
因此不将其描述为新增发布按钮的完整旧版实测。

## 26.3：布局与来源解耦、列表界面记忆

此前 `halfmasa$enabled` 将整个紧凑布局挂在合并来源开关上，适配层还会强制本地页签、
无条件读取两类路径点并替换原生页签栏。修复将布局启用、来源合并和页签处理分别判断：
只有合并模式才强制本地页签并组合数据；未合并的紧凑模式保留原生页签，使用其实际筛选结果。
切回单来源时恢复原页签；维度、路径点集或页签变化后重新计算紧凑滚动和选择控件。

“记住路径点列表界面”默认开启，受 Conflux Map 扩展总开关控制。
状态存于 HalfMasa 配置目录的 `conflux-waypoint-list.json`，按原生世界标识的 serverId/worldId 隔离。
记录页签、维度模式、路径点集、搜索文本、原生及紧凑滚动位置，不记录批量选择、删除确认、
弹出操作面板或发布请求。紧凑模式和来源顺序沿用现有持久配置。
列表移除时保存；初始化及默认设置应用后恢复，每个列表实例只恢复一次，避免编辑返回或窗口调整时覆盖当前操作。
当前世界标识不符时不把旧界面状态写进新世界；无记忆时保留现有打开默认设置。

恢复后由原生逻辑规范化失效分组和维度，公共页签不可用则回本地。
“仅当前维度”会被 Conflux 原生规范化为“当前维度”，这不属于丢失筛选。
滚动按当前内容夹取；数据文件格式异常时记录原因并使用打开默认值。
保存采用临时文件替换，失败保留脏标记以便下次关闭时重试，不在渲染 Tick 写盘。

`scripts/python/run_conflux_list_memory_smoke.py` 在真实客户端及独立测试服务器中验证来源与布局组合、
页签切换、关闭重开、磁盘重读、世界键隔离、分组删除、维度回退、滚动夹取及格式异常。
磁盘重读通过清除内存缓存执行，并非整套客户端进程重启验证。

本轮最终构建通过 45 项布局及记忆专项检查、42 项公共副本及选择框检查；
在 Conflux Map 0.1.10 上通过 1484 项原有界面断言（含几何参数组合）。
三组测试均使用隔离客户端及独立 Fabric 服务端、Java 25 `-Xint`。

## 2026-10-23：路径点功能跨版本同步

26.3 基线的公共副本快捷发布、紧凑右侧批量选择框、来源与布局解耦、列表界面记忆
现已同步到全部十个支持构建目标，随 1.7.2 发布。下述游戏内检查使用 1.7.1 开发构建，各目标逐版独立构建并归档。
每版搭配 Conflux Map 0.1.11，通过 45 项布局/记忆和 42 项公共发布/选择检查，共870项。
测试使用隔离真实客户端和独立 Fabric 服务端；原有26.3基线还曾在0.1.10上完成界面回归、
在0.1.12上验证新功能，不把这些基线结果等同于全版本Conflux矩阵验证。

生产代码处理旧版三参数鼠标输入和新版事件输入的区别；测试程序按版本重映射Minecraft符号，
保护Conflux自身的私有selectTab方法名，并在共享目录更新后等待原生界面Tick再断言最终条目数。
非26.3的专项测试通过同一悬停处理方法准备即时点击，界面仍由游戏原生入口正常渲染。

1.21.x 客户端采用Java21默认JIT；26.1.2/26.2采用Java25 `-XX:TieredStopAtLevel=1`，
26.3采用`-Xint`。26.1.2初次解释执行时线程栈显示原版全景背景纹理复制耗时较长，
主动结束该隔离测试后改用C1正式重测；该次中止不计入通过结果。这些是测试环境设置。
